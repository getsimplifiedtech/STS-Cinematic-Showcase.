# Hosting compatibility matrix (Gate 5 Phase 3, `APR-JE-031`)

Tags: **T** verified by existing tests, **D** verified by official provider documentation (as a search-tool summary of the page, 2026-10-11; see `README.md` for the limits), **L** requires live-host verification, **G6** requires implementation during Gate 6. The tag in bold is what is still open. "Probe" means the existing simulation was asked on 2026-10-11 for the URL (client-build fixture, nothing written to the repository). Row numbers are stable references (`M-xx`).

The site: 27 delivered files, 1,996,256 bytes, five pages (`index.html`, `menu.html`, `our-story.html`, `visit-us.html`, `order-online.html`), `styles.css`, three scripts, four fonts, hero video as MP4 and WebM, six WebP images. An indexable client build adds `sitemap.xml`, `robots.txt` and `llms.txt`. The fictional demonstration publishes none of the three and stays `noindex`.

## 1. Cloudflare Pages compatibility

| ID | Requirement | Finding | Class |
|---|---|---|---|
| M-01 | Deploys as a plain static folder, no build, function, `_worker.js`, `_routes.json`, `_redirects` or `wrangler` file | The folder passes `check:hosting` (no application, vendor, secret or redirect file; only static types). Pages serves a directory of static files. | T; **L** first deployment accepted |
| M-02 | Extension-less page URLs | Pages redirects `/contact.html` to `/contact` and `/about/index.html` to `/about/` (D, summary of *Serving Pages* and *Redirects*). The build refuses `seo.urlStyle: extension` for `seo.host: cloudflare-pages` (T, `check:seo`, `check:selftest-gate4`). The simulation models it with status 308 (probe: `/menu.html` gives 308 to `/menu`, `/index.html` gives 308 to `/`, query string kept). | T + D; **L** for the real status code, the `/index.html` form and query handling |
| M-03 | Trailing slash: `/menu/` | Not documented in the summary for Pages (the Workers static-assets *HTML handling* page describes an `auto-trailing-slash` default and was reported as the same behaviour, not confirmed for Pages). The site does not support `/menu/`: its links are relative, so a served `/menu/` would resolve `index.html` to `/menu/index.html` (documented in `check:portability`). Probe: the simulation answers 404. | **L** (HR-03) |
| M-04 | Unknown path (no `404.html` in the site) | Pages treats a project with no top-level `404.html` as a single-page application and serves `index.html` for paths that match no asset (D). The simulation answers 404 (probe: `/nope` gives 404). On this site: soft 404s on mistyped URLs; and on the demonstration `/robots.txt`, `/sitemap.xml`, `/llms.txt` would answer 200 with the home page. | D; **L** to confirm; owner decision D-P3-1 (HR-01) |
| M-05 | `_headers` syntax, one splat, limits | At most 100 rules and 2,000 characters per line; one splat per URL; named placeholders (D). `check:hosting` enforces the limits, valid names, the leading `/`, no repeated header in a rule, and that the CSP equals the computed one (T; 18 hosting negative tests in `check:selftest-gate4`). | T + D |
| M-06 | Several rules matching one URL | A request inherits the headers of every matching rule; a header set twice is joined with a comma (D). The generated file therefore puts security headers only in `/*` and `Cache-Control` only in narrower rules (T). That nothing is sent twice is not provable without a host. | T + D; **L** (count each header on the wire) |
| M-07 | Rule paths match the requested URL, not the file name | `_headers` is path based. The HTML cache rule is written `/*.html` (and `/` for Home). On a clean-URL host a page is requested as `/menu`, which the `/*.html` pattern does not match, so only `/` receives `Cache-Control: no-cache` from the file. The fallback is Pages' own default for static assets, `public, max-age=0, must-revalidate` (D), which also forces revalidation, so the effect is nearly the same. The simulation never applies cache rules (see M-30), so no test sees this. | **L**; **G6** (generate page-specific rules or a rule that matches clean URLs) (HR-02) |
| M-08 | Redirect responses and headers | Redirects are applied before headers, so `_headers` rules do not decorate a redirect response (D). Security headers on the 308 are therefore not delivered; the redirect carries no content, and the final response carries them. | D; **L** (record what the redirect carries) |
| M-09 | Security headers and CSP delivered unchanged | The CSP, the six other headers and HSTS come from `security.json`; every rendering is proven to carry the same values (T, `check:security`). With the headers served by the simulation, Chromium, Firefox and WebKit show zero violations, honour the six hashed `style` attributes and block an injected inline script, an unlisted style and an iframe (T, `check:security`, `check:d11`, `check:seo` browser step, in all three engines). Cloudflare does not modify an origin CSP except through Zaraz, and `_headers` is the mechanism for a Pages site (D). | T + D; **L** (does the real edge deliver them unchanged on pages, assets, 404 and the fallback) |
| M-10 | Provider features that change the HTML or add scripts | The CSP admits only `'self'` and the hashes of the built inline script and style attributes. Cloudflare Web Analytics' beacon loads from `static.cloudflareinsights.com` and needs a CSP change (D). Email Address Obfuscation injects a decode script and rewrites visible addresses in HTML (D); whether its script is allowed by this CSP is not documented. Any rewrite of the HTML bytes changes the hashes. | **L** (HR-08): turn the features off and compare served bytes with built bytes |
| M-11 | Preview and production indexing | Every Pages **preview** deployment carries `X-Robots-Tag: noindex`; the **production** `*.pages.dev` address does not, and a `_headers` rule using the host pattern `https://:project.pages.dev/*` can add it (D). Today the demonstration's `noindex` is a meta tag only (T, `check:seo`); the header is Phase 4 work. | D; **G6/Phase 4** (header); **L** |
| M-12 | Limits | 25 MiB per file on every plan; 20,000 files on the Free plan; **100,000** on paid plans since January 2026, enabled by an environment variable (D). `check:hosting` enforces 20,000 and 25 MiB (T, the conservative value). The site has 27 files and its largest file is 913,066 bytes. | T + D |
| M-13 | Cache policy for assets | `security.json`: HTML, CSS, JS `no-cache`; fonts and media `public, max-age=604800`; nothing marked `immutable` for unhashed names (T for the file contents). The hashed build (`npm run build:hashed`) exists for immutable caching and is not wired to any host. | T; **L** |
| M-14 | Content types, Range, compression for `.webm .mp4 .woff2 .webp .txt .xml` | Not documented per type in what was retrieved. The simulation sets its own types and its own Range logic. The hero video must be seekable and playable (Safari requires byte-range support for video; general knowledge, unverified). | **L** (HR-12) |
| M-15 | Custom domain, DNS, TLS, apex/`www` redirect | Outside the repository and outside the simulations. | **L** (HR-15) |
| M-16 | Deployment method | The repository name ends with a dot. Whether provider Git integrations accept such a name is not established (general knowledge, unverified). A direct upload of a staged bundle avoids the question. | **L**; **G6** (staging step) (HR-07) |
| M-17 | Platform direction | The Cloudflare documentation now has a *Migrate from Pages to Workers* guide, and the Workers static-assets pages repeat the same `_headers` limits. `_headers` and clean-URL behaviour appear shared. Whether Pages remains the recommended target is not asserted here. | D; Gate 6 adapter should name its target explicitly (HR-16) |

## 2. Vercel compatibility requirements

| ID | Requirement | Finding | Class |
|---|---|---|---|
| M-20 | `cleanUrls` | Default `false`. When `true`, files lose their extension and a request that still has it gets a 308 to the extension-less path; rewrite and redirect sources must then omit the extension (D, *Static Configuration with vercel.json*). Simulation profiles `vercel-clean` and `vercel-default` reproduce both (T, `check:seo`; probe: default Vercel answers `/menu` with 404, serves `/menu.html` as named). The build requires `seo.urlStyle` to match (T). Writing `cleanUrls: true` into a deployment has no implementation. | T + D; **G6** |
| M-21 | `trailingSlash` | Default is undefined: `/about` and `/about/` both serve the content without redirecting, which Vercel itself does not recommend (duplicate content). `false` sends a 308 from the slashed path to the bare path; `true` does the reverse (D). With `cleanUrls: true` and `trailingSlash` unset, `/menu/` would serve the page and the relative links on it would break. The simulations model no trailing-slash behaviour (probe: 404). | D; **G6** (set `false` explicitly); **L** (HR-03) |
| M-22 | `headers` | An array of `{ source, headers: [{ key, value }] }`; `source` is a pattern matched against the pathname without the query string; the documented global form is `/(.*)`; entries may be conditional with `has` and `missing` (D). Rendering from `security.json` has no implementation. Whether `source` is matched before or after `cleanUrls` rewriting, whether several matching entries combine or override, and any limit on the number or size of entries were not established. | D; **G6**; **L** (HR-02, HR-06) |
| M-23 | Output directory, build command, framework | For a plain static site: framework preset **Other** (`"framework": null`), build command blank, and `outputDirectory` to serve a folder other than `public` or the project root (D). `outputDirectory` in `vercel.json` overrides the dashboard setting (D). The exact keys for "no build and no install" were not confirmed beyond that. | D; **G6**; **L** |
| M-24 | Where `vercel.json` lives | Reported by the Vercel community, not the official page, that it must be at the root of the project, not in a subfolder (unverified). This repository's site is in `jade-and-ember/`. `check:hosting` forbids `vercel.json` in the delivered folder (T), so the adapter must write it **outside** the site folder, in a staged bundle (`bundle/vercel.json` plus `bundle/site/`). | **G6**; **L** (HR-06) |
| M-25 | Default caching of static files | `Cache-Control: public, max-age=0, must-revalidate` by default (browser), static files cached at the edge after the first request for up to 31 days (D, with a note that the pages are not fully consistent). Custom `Cache-Control` per path is set in `vercel.json` `headers`. | D; **L** (after a redeploy, is the edge copy replaced) |
| M-26 | Strict-Transport-Security | Vercel sends `max-age=63072000` by default on its domains, without `includeSubDomains` or `preload`; it can be changed with custom response headers, but a community thread reports an override that did not appear (D, partly unverified). Our value is `max-age=31536000; includeSubDomains`. | D; **L** (HR-09) |
| M-27 | Previews | New projects default to Standard Protection, which protects preview deployments and leaves production domains public; generated preview URLs carry `X-Robots-Tag: noindex`; a custom domain on a non-production branch does **not** receive it automatically (D; two Vercel sources name the default differently, Standard Protection versus Vercel Authentication). A reviewer therefore cannot open a protected preview without signing in or a share link. | D; **L** (HR-10) |
| M-28 | Preview and staging hosts in production | `*.vercel.app` and `*.pages.dev` are refused as a production domain by the release gate (T, `check:release`). | T |
| M-29 | No vendor dependence | No source, configuration, delivered file or rule refers to Vercel; `check:hosting` fails if one does (T). An adapter must be allowed to name Vercel in its own code and its own output, so the check must become adapter-aware. | T; **G6** |

## 5. Root versus subpath hosting

| ID | Requirement | Finding | Class |
|---|---|---|---|
| M-60 | The folder works at the root and below a path | `check:portability`: file://, domain root, `/clients/acme/jade-and-ember/`, the directory URL without its slash (redirected), extension-less URLs, no Range, query strings, in Chromium, Firefox and WebKit (T). | T |
| M-61 | Pretty URLs with a trailing slash | Not supported (documented, relative links). | T (documented limit); **L** on a real host |
| M-62 | `_headers` under a path | `npm run host:files -- --prefix /sub` writes every rule under the prefix; `check:hosting` proves the rules start at the prefix (T). That is correct only when the deployed asset directory itself contains the `sub/` folder. If a proxy or rewrite removes the prefix before the request reaches the host, no prefixed rule matches and no security header is sent. | T; **G6** (distinguish "mounted at" from "stored under"); **L** (HR-02) |
| M-63 | Cloudflare Pages subpath | A Pages project is addressed by hostname; a path on another hostname needs a proxy, a Worker or a route (plan statement; general knowledge, unverified). | **L**; D-P3-2 |
| M-64 | Vercel subpath | Needs a rewrite from another project or a monorepo layout; headers and `cleanUrls` then apply per project. Not established. | **L**; **G6** |
| M-65 | Search files at a subpath | `robots.txt`, `sitemap.xml` and `llms.txt` are only read at the root of the hostname, so an indexable build must be at a hostname root. | T (warning); recommendation D-P3-2 |
