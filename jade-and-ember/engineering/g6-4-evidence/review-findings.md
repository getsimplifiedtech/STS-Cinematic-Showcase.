# G6-4: independent review of the hosting adapters, and what became of each finding

A separate reviewing session (a model, not a person; it was given the code and asked to attack it, read-only) reported 18 findings against the first complete version. The existing tests all passed at that time, so none of them had been caught. All were addressed or documented; each fix has a negative case in `checks/hosting-adapters.mjs` and a mutant in [`adapter-mutations.md`](adapter-mutations.md). This is a model review, **not** human verification, and is not recorded as one.

| # | Severity | Finding | Disposition |
|---|---|---|---|
| 1 | High | `--out` could delete the delivered folder, its parent, or any folder (the bundle writer emptied its output folder unguarded) | **Fixed**: the output folder is refused if it is, contains or sits inside the delivered folder, contains the working folder, or is a non-empty folder that is not an earlier bundle |
| 2 | High | The deployed-bytes comparison accepted altered content at the `.html` form of a page on a clean-URL host, and could not tell a 404 from a 200 | **Fixed**: the `.html` form, `/index.html`, `/index` and `/404` are "served but must not be"; an optional unknown-path probe fails a soft 404; the CLI no longer maps `404.html` to `/404` |
| 3 | High | `SETTINGS.txt`, `unverifiedLive`, `settingsToApply`, unknown manifest fields and credential-shaped text were never checked | **Fixed**: those files and fields are written again and compared; the manifest has a fixed field list; every file of a bundle is scanned for credential-shaped text; an https domain-root base URL without a user name is required |
| 4 | Medium | The HSTS "recorded authorisation" was a format check; the flag was truthy-typed | **Fixed**: the reference must be listed in `security.json` `hstsOptions.authorisations` (empty today); `includeSubDomains` must be a boolean; unknown options (preload) are refused. The tool still cannot check what the named record says |
| 5 | Medium | The Cloudflare status of a `404.html` response was assumed and not listed as unverified | **Fixed**: listed in the manifest, `SETTINGS.txt` and the profile's assumptions; the fact CF-09 no longer claims a status |
| 6 | Medium | Nested css/js under `fonts/` or `media/` got conflicting cache rules; Vercel covered only top-level code files | **Fixed**: stylesheets, scripts and pages are refused inside the asset folders; Vercel gets an exact entry for every css/js file at any depth |
| 7 | Medium | The simulation answered `/404`, `/404.html` and (Cloudflare) `/index` with success | **Fixed**: modelled as unknown paths, tested, and listed as unverified |
| 8 | Medium | Nested and upper-case-extension HTML, folder/page collisions and wrongly cased search files passed | **Fixed**: refused |
| 9 | Medium | The declared URL style was never reconciled with the site | **Fixed**: the sitemap and canonical links must use the declared style |
| 10 | Medium | `config/`, `src/`, `tests/` were accepted into a delivered site; the real-site test hid this | **Fixed**: project folders refused; the real-site test now keeps nothing hidden |
| 11 | Medium | The simulation server's profile branch had no root-escape guard (`/..%2fvercel.json`) | **Fixed**: guarded in the profile and in the server; tested |
| 12 | Medium | Soft-404 content and search-file content were not checked; a noindex `404.html` was refused as "mixed" | **Partly fixed**: an empty 404, a copy of the home page, a meta-refresh 404 and empty search files are refused; a `404.html` may carry noindex or not. The meaning of `robots.txt` (for example `Disallow: /`) stays with `check:seo` |
| 13 | Medium | Some provider-fact statements went beyond their quotes; a platform-default assumption was unlisted; messages said "twice" where the documentation says "joined" | **Fixed**: statements cut back and split (47 facts); every verbatim fact lists the words of its statement that its quote must contain and the check enforces it; the `_headers`-overrides-default assumption is listed; wording corrected. The Pages file limit stays at the free plan's 20,000, as stated |
| 14 | Medium | Vercel claims without a fact (preview protection default), the `*.vercel.app` HSTS preload, the named-segment inference | **Fixed**: claims softened or listed as unverified; the HSTS row now says the never-preload rule cannot apply on `*.vercel.app` |
| 15 | Medium | `--verify-served` false-positived on a correct clean site with a `404.html` | **Fixed** |
| 16 | Low | Tests compare the profile with the author's own assumptions; the static profile and Vercel-without-404 were not walked | **Partly fixed**: the static profile and the unknown-path answer without a 404 are now walked; a profile can only ever show internal consistency with the documented behaviour, which the README and report say |
| 17 | Low | Prototype keys (`constructor`) as adapter names and a `null` manifest crashed instead of reporting | **Fixed** |
| 18 | Low | The existing nginx and Apache renderings scope cache rules differently from `_headers` and `vercel.json` | **Documented** in the adapter README; only the security headers are compared across renderings |

One further defect was found by the existing release dry run, not by the review: page cache rules written in registry order by the release tool and in file order by the package verifier made every release package fail verification. Fixed (rules sorted) and guarded by a test.
