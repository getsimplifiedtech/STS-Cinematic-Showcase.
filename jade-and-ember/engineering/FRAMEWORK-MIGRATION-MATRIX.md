## 1. Classes

| Class | Meaning |
|---|---|
| `universal` | Reusable across all STS client websites with parameterisation only (values move to the project manifest; logic is unchanged). |
| `universal-redesign` | Reusable only after a design change (a mechanism that encodes a Jade & Ember assumption, or a finding from Phases 5 to 7). |
| `adapter-industry` | Belongs to one industry (restaurant) and stays with projects of that industry. |
| `adapter-hosting` | Belongs to one hosting provider or delivery mode. |
| `project` | A fact about Jade & Ember or its delivered site; stays. |
| `devtool` | Development and test tooling; kept optional, never a release dependency. |
| `record` | Project history, decisions and evidence; stays. |
| `doc` | Documentation that is rewritten into the framework specification. |

## 8. Operating principles stated by the owner (APR-JE-037)

- **OP-1** Anthropic Frontend Design is the sole creative authority; STS engineering enforces technical standards and never dictates aesthetic choices. (clarification 5)

- **OP-4** GitHub Actions is the foundation for centralised maintenance and security; nothing is installed on a client host. (clarification 8)
- **OP-5** Claude implements; ChatGPT reviews evidence and architecture; the owner authorises releases; automated verification is independently reproducible (every claim carries the command or the CI job that reproduces it). (clarification 9)
- **OP-6** Framework consumers pin Git revisions; the master framework repository owns the reusable engineering and is not modified without the owner's explicit approval. (clarifications 1 and 2)
